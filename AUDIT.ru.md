# GachaPoint Data Hub — отчёт об аудите

Дата: 09.11.2026.

## Кратко

Плановый workflow `Sync Promocodes and Schedule` падал с 08.11.2026.
Опубликованная ветка `main` всё ещё содержала данные старого парсера:
непроверенные активные коды с искусственными датами истечения и баннеры
`CURRENT`/`ANNOUNCED` без официальных источников.

В рамках аудита падение было воспроизведено, небезопасное слияние заменено на
схему «сначала карантин», добавлена проверка по официальным источникам и
усилен линтер, чтобы такие данные больше не публиковались.

## Состояние пайплайна до исправления

- Последний успешный плановый запуск: `42443584936` (08.11.2026 03:38 UTC).
- Упавшие запуски: `42576011096`, `42529451723`, `42498185720`.
- Шаг падения: `Run lint and integrity validation` после sync.
- Причина: старый sync повторно публиковал `KEEPUPWITHMITYA` с наградой
  `Камни Истока` без количества, строгий линтер это отклонял. Шаг commit
  пропускался, поэтому обновления каждого запуска терялись.

## Найденные проблемы данных

- 28 `ACTIVE`-кодов в `main` не имели `verification_status` и использовали
  искусственные даты истечения (`2026-11-26T06:32:4x`,
  `2026-12-09T12:00:00Z`).
- HSR `hsr_4_6_2`, `hsr_4_7_1`, `hsr_4_7_2`, ZZZ `zzz_3_3_1`, `zzz_3_3_2` и
  HI3 `hi3_9_1_1` были `CURRENT`/`ANNOUNCED` без `source_url`,
  `verification_status` и `verified_at`.
- У `JRNY2SKY` было испорчено русское описание наград
  (`300 ??????????, 30 000 ?????...`).
- `YUANSHEN` был `EXPIRED`, но имел `expires_at` в будущем.
- 19 старых HI3-кодов использовали искусственные даты `2023-01-01` /
  `2023-01-31`.
- `ZZZTVCM` считался бессрочным; `CODE_VERIFICATION.md` и
  `QUARANTINE_CODES.md` расходились с JSON-данными.

## Что изменено

- `scripts/parsers/official_codes_parser.py` ищет коды в официальных
  объявлениях Genshin, новостях HSR/ZZZ/HI3 и официальных новостях HoYoLAB.
  Код публикуется автоматически, только если точное значение найдено в
  официальном тексте и из окружения извлекаются количества наград.
- `scripts/sync/sync_promocodes.py` теперь отправляет непроверенные активные
  коды в карантин до публикации, сверяет их с официальными текстами,
  отправляет неоднозначные случаи в Telegram и не позволяет записать пустой
  или резко уменьшившийся `banners_schedule.json`.
- `scripts/tools/apply_code_checks.py` поддерживает `--set` и `--list-pending`,
  чтобы применять результат проверки из Telegram одной командой.
- `scripts/tools/lint_data.py` отклоняет битые символы, будущую дату истечения
  у `EXPIRED`, непроверенные активные коды, неожиданные `PERMANENT`,
  ссылки на индекс новостей вместо конкретного поста и дубли между карантином
  и опубликованными данными.
- `.github/workflows/sync.yml` проверяет закоммиченные данные, стандартные
  пулы и тесты парсеров перед sync.
- `.github/workflows/verify-code.yml` применяет одну ручную проверку и
  пушит результат.

## Кросс-репозиторная заметка

Android-клиент теперь игнорирует удалённый датасет, если его `updated_at`
старше закэшированной копии. Это не позволяет устаревшей ветке `main`
откатить исправленные assets, поставленные с приложением.

## Политика проверки

1. Точное совпадение в официальном тексте + награды → публикация автоматически.
2. Совпадение без наград или отсутствие совпадения → карантин и дайджест в
   Telegram.
3. Проверка в игре → `source_type: manual_in_game`,
   `verification_status: verified`, `verified_at`.
4. Fandom используется только для обнаружения; сам по себе он ничего не
   публикует.

## Ограничение

Многие коды HoYoverse публикуются только на изображениях (инфографика стримов,
посты в X). Пайплайн не выполняет OCR, поэтому такие коды нельзя подтвердить по
тексту — они всегда требуют шага проверки через Telegram. Официальные посты с
текстом проверяются автоматически.

## Локальные команды

```bash
python -m unittest discover -s tests
python -m scripts.tools.lint_data --strict
python -m scripts.tools.apply_standard_pools --check
python -m scripts.sync.sync_promocodes --no-scrape
python -m scripts.tools.apply_code_checks --list-pending
```

## Критерии приёмки

- Тесты парсеров и строгий линтер проходят на локальных, удалённых и
  post-sync данных.
- Три подряд запуска `workflow_dispatch` и один плановый запуск зелёные.
- У каждого `ACTIVE`-кода есть официальный источник или проверка в игре.
- У каждого баннера `CURRENT`/`ANNOUNCED` есть официальный detail-`source_url`,
  `source_id`, `verification_status: verified` и `verified_at`.
- В опубликованных данных нет искусственных дат и битых символов.
